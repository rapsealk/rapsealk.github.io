# Medium-Style Layout & UI Reimplementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task, or execute directly task-by-task. Planning only — nothing below has been implemented yet.

**Goal:** Reorganize the whole blog layout and UI to match Medium's reading experience (680px column, big vertical rhythm, gray meta lines, sticky minimal header) with full mobile support, keeping the orange brand color and Pretendard Korean typography.

**Architecture:** Pure CSS + JSX restructure — no config or data changes. Three surfaces: sticky 57px top bar, Medium-style home feed (article cards), and a Medium article page (byline with read time, 680px serif-rhythm column, author footer card). Everything ships as one feature branch + PR against `master`.

**Tech Stack:** Gatsby 5 (existing), `gatsby-transformer-remark` built-in `timeToRead` field, plain CSS custom properties in `src/style.css`, CDP-driven viewport screenshots for visual verification.

## Findings (measured evidence)

**Premise check:** Medium's live site Cloudflare-blocked the fresh browser session, so measurements were taken from the Wayback Machine render of the reference article (`web.archive.org/web/20260724034053/https://medium.com/@f8010/...`). Values below are **computed styles read from the rendered page**, not guesses. One caveat: Wayback rewrites Medium's runtime JS, so the sticky-header behavior was not measurable — header spec below is marked "known spec".

### Medium article page — desktop (1280×577 viewport)

| Element | Measured |
|---|---|
| Content column | **680px** (title, body, h2, figcaption, lists all 680px) |
| Title `h1` | sohne (sans), **42px / 700**, line-height **52px**, letter-spacing **−0.011em**, color **#242424** |
| Section `h2` | sohne, **24px / 600**, line-height **30px**, letter-spacing **−0.016em**, margin-top **≈47px** (big section gaps) |
| Body `p` | **source-serif-pro (serif), 20px / 400, line-height 32px (1.6)**, letter-spacing −0.003em, #242424, paragraph gap **≈43px** |
| List `li` | 20px / 32px, margin-left **30px** |
| `figcaption` | **14px, centered, #6b6b6b**, margin-top 10px |
| Meta line (read time · date) | **14px, #6b6b6b** |
| Text color | **#242424** everywhere; meta/captions **#6b6b6b** |

### Medium — mobile (375×812 viewport)

| Element | Measured |
|---|---|
| Title `h1` | **32px / 38px** |
| Body `p` | **18px / 28px (1.56)** |
| Column | fluid, 327px wide at 375px viewport → **24px side padding** |

### Premise checks against the user's premise

- *"Align with medium"* → the defining Medium traits are the **680px column, the giant vertical rhythm (≈43px paragraph gaps, ≈47px section gaps), gray 14px meta/caption text (#6b6b6b), and near-black #242424 text** — not the green brand color or the serif body font.
- **Serif body ≠ for Korean.** Medium renders CJK posts in sans (Noto Sans KR). Our blog is Korean with Pretendard — keeping Pretendard *is* the Medium-faithful choice. The Latin-serif look cannot be replicated for Korean text (see Open questions).
- **Green → orange.** Medium's brand green (#1a8917) is replaced by our existing brand orange `#cb4a0d` everywhere green would appear (links, follow-style buttons, hover states).

## Risks, tradeoffs, open questions

- **PR #4/#5 merge order (blocking):** the redesign rewrites `index.js`/`style.css` those PRs touch. Default: merge both first, then branch — the redesign re-carries load-more and OG cards (Task 0).
- **Serif body look won't transfer.** Medium's body is a Latin serif; Korean Medium renders sans (Noto Sans KR). We keep Pretendard — correct for Korean, but the "serif reading texture" is intentionally not replicated. Open question: add a Latin-only serif (e.g. source-serif-pro via fontsource) for Latin glyphs with Pretendard fallback for Hangul? Default: **no** — two-font mixing for a mostly-Korean blog adds weight for marginal gain.
- **Header spec is "known spec"**, not measured: Wayback rewrites Medium's runtime JS so sticky/scroll-border behavior wasn't observable. Default: sticky, always-on 1px hairline (simpler; matches most Medium screenshots).
- **Raw dates in front matter** (`2022-04-24`) are fine — formatting happens in the template; front matter untouched (posts stay verbatim).
- **`.og-card` / Prism styles** must be re-checked after the rhythm change (Task 4 syncs margins; code-block background unchanged).
- **Footer copyright year** becomes dynamic (`new Date().getFullYear()`) — the current footer already does this.
- **No-JS behavior:** load-more keeps first 6 visible without JS (PR #4 behavior preserved); all other layout is CSS-only.
